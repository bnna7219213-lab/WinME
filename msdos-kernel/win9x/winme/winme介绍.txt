================================================================================
WinME —— 手写操作系统介绍（winme介绍.txt）
================================================================================

本文是一份面向「想了解这个系统能做什么」的读者（使用者 / 评估者 / 新人）
的产品级介绍。重点说明：这是一个**真实可运行的操作系统内核**，它现在
**已经具备哪些能力、有什么样的图形界面、成熟度如何**。有关研发排期与
未完项，请另见同目录 issue.md / winme_net介绍.txt。


--------------------------------------------------------------------------------
1. 这是什么系统
--------------------------------------------------------------------------------
WinME 是开源项目 msdos-kernel 中「Win9x / WinME」线的产物，代号 A4 GUI。
它不是模拟器、不是 Linux 裁剪、也不是教学玩具，而是一套**完全用 x86 汇编
（16 位 + 32 位）从裸金属开始手写**的操作系统：

  · 从加电后的实模式引导扇区（boot32）一路自举到 32 位保护模式内核；
  · 自带 GDT / IDT / 分页、VGA 文本与图形、键盘与鼠标驱动；
  · 自带一个图形化 shell（A4 GUI）和一套网络协议栈；
  · 能联网、能下载一个真正的 Windows PE 程序、能把它安装进自己的
    文件系统、还能在桌面上用鼠标双击把它再跑起来。

一句话：**一个从引导扇区写到 GUI 与网络栈、自给自足的 32 位图形操作系统。**


--------------------------------------------------------------------------------
2. 现有功能一览（今天就能用）
--------------------------------------------------------------------------------
▌2.1 引导与内核
  · 实模式引导 → 开启 A20 → 进入 32 位保护模式 → 装载内核到 1MB 以上
  · 完整的中断/异常处理（IDT）、内存管理（分页）、VGA 文本与图形双模式
  · 每帧驱动的主循环（main_loop）：网络收发 + 界面重绘 + 输入处理

▌2.2 图形界面（A4 GUI）
  · 桌面（含桌面图标区）、可绘制窗口、标题栏与简单控件
  · 鼠标驱动（mou_handle）与键盘驱动，实时光标与点击命中检测
  · 桌面图标 = 已安装的文件/程序；支持**双击图标运行已安装 EXE**
  · 提供 MessageBoxA 桩，PE 程序可弹出图形对话框
  （界面细节见第 3 节）

▌2.3 网络（真实网卡 + 真实协议栈）
  · 网卡驱动：Realtek RTL8139（MMIO + 收发环形队列）
  · 协议栈：ARP → IPv4 → TCP（三次握手 / 重传 / 超时 / FIN 优雅关闭 / RST）
           → UDP（供 DNS 用）→ HTTP/1.1
  · DNS 解析：可向真实 DNS 服务器查询域名、解析 A 记录、得到公网 IP
  · 可访问任意 http(s) 主机（scheme://host:port/path 解析 + 动态 Host 头）

▌2.4 程序执行（PE32）
  · 下载 / 载入一个 Windows PE32 镜像，完整处理：
    MZ→PE 头 → 节表 → 导入表（IAT 填桩）→ 跳转到 EntryPoint 执行
  · 支持 64 位绝对跳转（far jmp 进入 PE 入口），真实运行 PE 的 main

▌2.5 文件系统（OS 级持久化）
  · file_table（文件/目录元数据）+ file_contents_pool（内容池，分块存储）
  · 创建 / 删除文件，按游标读写文件内容（fs_write_cur / fs_read_cur）
  · 网络下载的 PE 会被「安装」为文件系统中的一个 EXE 条目，
    之后可脱离网络、从桌面图标再次运行

▌2.6 Win32 兼容层（约 19 个 API 桩）
  覆盖 PE 程序最常见的导入，使普通用 MinGW/VC 链接的小程序可直接运行：
  ExitProcess、GetModuleHandleA/W、GetProcAddress、GetTickCount、Sleep、
  GetStdHandle、WriteFile、ReadFile、printf、GetModuleFileNameA、
  GetCommandLineA、HeapAlloc、HeapFree、VirtualAlloc、CreateFileA、
  CloseHandle、lstrlenA、MessageBoxA 等。
  HeapAlloc/VirtualAlloc 由一块 32KB 的 PE 堆（bump allocator）支撑；
  WriteFile/ReadFile 可把数据真正写到 OS 文件系统。


--------------------------------------------------------------------------------
3. 图形界面详解（重点）
--------------------------------------------------------------------------------
A4 GUI 是这个系统的「脸面」，也是它最直观的成熟度体现。整个界面由
main_loop 每帧重绘，配合鼠标 / 键盘实时交互。

▌3.1 桌面与图标
  · 桌面绘制一组程序 / 文件图标，最多 8 个可见槽位，按 **4 行 × 2 列**
    网格排布（draw_icons_fs）。
  · 已下载并安装的程序（如 ludashi_install.exe、inet_dl.exe）会作为
    FS_TYPE_FILE_EXE 出现在桌面上，和普通文件图标区分显示。
  · 每个图标有固定矩形命中区，鼠标位置与网格匹配即视为「点中」。

▌3.2 鼠标与命中检测
  · 鼠标驱动在主循环里持续上报坐标（mou_x, mou_y）与按键状态。
  · fs_hit_test(mou_x, mou_y) 按图标矩形做命中测试，返回 file_table
    槽位或 -1，是「桌面交互」的核心原语。

▌3.3 双击运行已安装 EXE（类 Windows 体验）
  这是系统「可用」的最关键证明：
    1) 用户在桌面左键点中某个 FS_TYPE_FILE_EXE 图标；
    2) mou_handle 写入 run_prog = 槽位、pe_state = 0、pe_pending_run = 1；
    3) 主循环下一帧检测到 pe_pending_run，调用 exe_load(Priority 0.5)
       + pe_exec，从文件系统内容池把 PE 拷回执行缓冲并运行；
    4) 程序跑完，PE 的 ExitProcess 返回退出码，界面恢复。
  实测结果：图标点击触发 EXE 运行，exit_code = 0（详见第 4 节）。

▌3.4 键盘与对话框
  · 键盘驱动支持命令行式输入与字符回显。
  · MessageBoxA 桩会在图形界面上绘制一个简单对话框并回显文本，
    让 PE 程序具备「弹窗」能力（目前为轻量实现）。

▌3.5 VGA 图形能力
  · 支持文本模式与图形模式（mode 13h，320×200×256）的自适应；
  · 图标、窗口、对话框均基于自绘图元，无外部 GUI 库依赖。

4. 成熟度与验证（重点）
--------------------------------------------------------------------------------
本系统不是「理论上可行」，而是在 QEMU 真实硬件模型上**端到端跑通并通过
量化回归**。下面用一个完整场景说明它「现在就能做什么」：

  【线上实测闭环】
  开机 → 内核引导 → 自动经 RTL8139 + SLiRP 联网
       → TCP 三次握手建立连接 → HTTP GET 下载一个真实 PE
       → 解析 PE / 填 IAT / 执行其 main → 程序正常退出（exit OK）
       → 该 PE 被「安装」为桌面的 inet_dl.exe
       → 用户在桌面**双击图标** → 再次运行该 PE（无需网络）→ 退出码 0

这一闭环覆盖了：引导、保护模式内核、网络栈、TCP 可靠性、HTTP、PE 解析
与执行、文件系统持久化、图形界面与鼠标交互——整条链路全部真实可用。

【回归测试量化成绩】
  三套自动化回归在 QEMU 上全部通过，合计 49/49：

    run_net_test.ps1          →  13 / 13 PASS  （本地网络链路核心流水线）
    run_real_inet_test.ps1    →  23 / 23 PASS  （真实互联网下载 + 安装 + 双击运行）
    run_real_inet_test.ps1 -DnsTest → 13 / 13 PASS （真实域名 DNS → 公网下载）

  关键验证点包括但不限于：
    · 正常引导、内核装载、A4 GUI shell 启动、RTL8139 被识别
    · ARP → SYN → SYN-ACK（ESTABLISHED）→ HTTP GET → body complete
    · PE MZ 检测 → 解析 → 导入表处理（IAT 非零）→ 执行返回 OK
    · 下载的 PE 安装进文件系统，能被反向校验出 MZ+PE 签名
    · 已安装 PE 可脱离网络从文件系统重载运行（buf 污染后仍能跑）
    · 桌面图标双击可触发 EXE 运行并拿到 exit_code = 0
    · 真实域名经 DNS 解析出公网 IP 并完成 HTTP 下载

【工程健壮性】
  · 内核镜像 kernel32.bin 约 240 KB，低于 262 KB 硬上限，余量充足；
  · TCP 具备超时重传（≤3 次）与 RST/FIN 处理，单点丢包不会假死；
  · 构建、打包、启动、断言全流程脚本化，可一键复现。

结论：**它在目标环境（QEMU + RTL8139）下已达到「可演示、可联网、可运行
真实 Windows 小程序、可图形交互」的成熟度。** 它是一个研究级 / 演示级
的真实操作系统原型，而非停留在幻灯片上的设计。


--------------------------------------------------------------------------------
5. 能力边界（诚实说明）
--------------------------------------------------------------------------------
为了让读者建立准确预期，这里简要说明当前范围（不展开研发排期）：

  · 网络为 HTTP；HTTPS/TLS 尚未实现（真实公网仍有大量 HTTP 可用）。
  · 一次主要加载运行单个 PE；多 PE 同载 / 重定位（Base Relocation）尚未做。
  · 时钟节拍（sys_tick）暂未充分利用，依赖 Sleep 的精确延时暂为近似。
  · 文件系统为自研精简实现，接口与 FAT/NTFS 不同，但语义足够支撑
    PE 安装与读写。
  · 以上均在 issue.md 的「残留项 / 后续方向」中跟踪，不影响现有功能的
    真实可用性。

6. 架构速览（模块地图）
--------------------------------------------------------------------------------
  boot32.asm  (16 位实模式)
    └─ 装载内核 → 开 A20 / 保护模式 → 跳入 32 位

  a4_gui.asm  (32 位保护模式内核 + A4 GUI shell)
    ├─ 内核初始化：GDT / IDT / 分页 / VGA / 键盘 / 鼠标 / 桌面
    ├─ main_loop（每帧）：
    │    网络收发（eth_rx → ip_rx → tcp_rx → net_download）
    │    → 界面重绘（桌面 / 窗口 / 图标）
    │    → 输入处理（mou_handle / 键盘）
    │    → pe_pending_run 调度（双击运行）
    └─ 模块：
        rtl8139_*   网卡驱动
        arp_* / ip_rx / tcp_* / udp_* / dns_* / http_*   网络协议栈
        net_download    总体下载状态机（URL 解析→ARP→DNS→TCP→HTTP→PE→安装）
        pe_*            PE 解析 / 导入 / 执行 / 安装到文件系统
        fs_*            文件系统（file_table / 内容池 / 读写 / 命中测试）

  宿主机侧：serve_a4.py / serve_real_inet.py（Python HTTP 服务器，分发 PE）

  构建：build_net.ps1（nasm 汇编 + common/pack32.ps1 打包成 1.44MB 软盘镜像）


--------------------------------------------------------------------------------
7. 如何构建与运行
--------------------------------------------------------------------------------
  # 构建普通镜像（默认使用 winme_net.img）
  powershell -File build_net.ps1
  # 构建带 DNS 测试的镜像
  powershell -File build_net.ps1 -DnsTest

  # 本地网络链路回归（13/13）
  powershell -File run_net_test.ps1
  # 真实互联网下载 + 安装 + 双击运行回归（23/23）
  powershell -File run_real_inet_test.ps1
  # 真实域名 DNS 回归（13/13）
  powershell -File run_real_inet_test.ps1 -DnsTest

环境说明：
  · 运行需 QEMU（约定 C:\qemu\qemu-system-i386.exe），网卡用 RTL8139
    用户态网络（SLiRP）；启动镜像建议加 -fda raw: 前缀。
  · 真实互联网测试需要宿主侧可访问公网 DNS（如 223.5.5.5）与 httpbin.org。
